# Phase 10: AWS persistence — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The engine's entities, blobs, work queue and LangGraph checkpoints persist in DynamoDB, S3 and SQS in ap-southeast-2 behind the phase 1 Protocols, selected by one setting. The phase 1 repository and runner tests pass on both backends offline under moto, and an opt-in smoke run passes against the real dev stack.

**Architecture:** Five DynamoDB adapters in `core/repositories/dynamodb.py` implement the phase 1 repository Protocols over the one `contextforge` table of spec 7.2 and 7.3. Every key string and the item codec live in `core/repositories/dynamodb_items.py`: camelCase attributes come from the entity aliases, and floats travel as Decimal. Rules both backends share (usage sums, the unanswered-entry rule, chat order, paging) move into `core/repositories/shared.py`, so memory and DynamoDB differ only in I/O. `S3BlobStore` and `SqsQueue` sit beside the in-memory implementations in `core/storage.py` and `core/queue.py`. Checkpoints go to the same table through the maintained `langgraph-checkpoint-aws` `DynamoDBSaver`. `scripts/aws_dev_stack.py` adopts the stack that already exists (or creates it), idempotently, and `core/backends.py` picks memory or AWS from `Settings.backend`. Streams-to-Lambda dispatch, real identity and per-user budgets stay later.

**Tech Stack:** Python 3.12, `uv`, boto3 low-level clients with `boto3-stubs`, `pydantic-settings`, `langgraph-checkpoint-aws` (`DynamoDBSaver`), moto 5 (`mock_aws`), pytest, ruff, mypy strict.

**Spec:** `docs/implementation-plan.md` sections 3 (entity fields), 7.1 to 7.8 (DynamoDB physical design), 11.2 to 11.4 (paging, uploads, downloads), 12 and 12.1 (layout, naming); `docs/system-design.md` sections 9 (dispatch and files), 11 (cost) and 14 row "10 AWS persistence"; `docs/progress.md` section "AWS resources" (the stack that already exists). Read them before any task. Prerequisites P1 to P5 are at the end of this plan.

## Global Constraints

- Python 3.12; `uv` with a committed `uv.lock`; `pytest`, `ruff check`, `ruff format --check` and `mypy --strict` (over `src` and `scripts`) clean before every commit. Tests live alongside the code they cover and are few, clubbed and integration-focused, one module per task where possible. Functions stay under about 40 lines, with no duplicated logic blocks.
- Region `ap-southeast-2`. Credentials come from the boto3 default chain or the profile named by `CONTEXTFORGE_AWS_PROFILE` (locally `contextforge`), never from an access key in code, `.env` or tests. `core/aws.py:aws_session` is the only place a `boto3.Session` is made.
- One table `contextforge` with string keys `PK` and `SK`, on-demand. Keys exactly as spec 7.2: Chat `USER#<userId>`/`CHAT#<chatId>`; Message `CHAT#<chatId>`/`MSG#<messageId>`; Artifact `CHAT#<chatId>`/`ART#<artifactId>`; Task `REQ#<requestMessageId>`/`TASK#<taskId>`; ModelCall `REQ#<requestMessageId>`/`CALL#<modelCallId>`; idempotency record `IDEMP#<clientKey>`/`REQ` with attribute `ttl`, 24 hours. User, IntegrationConnection and IntegrationTool keys arrive with their repositories.
- Index exactly as spec 7.3: `GSI1`, sparse (Artifact items only), `GSI1PK = USER#<userId>`, `GSI1SK = ART#<artifactId>`, projecting `indexStatus`, `kind`, `name`, `chatId`.
- Attribute names are camelCase, produced by the entity aliases (`by_alias=True`). Ids inside keys are also stored as plain attributes, so code never parses a key string. No code outside `core/repositories` and `core/storage` builds a key string or a blob key (spec 7.8); the dev-stack script imports prefixes from those modules.
- Conditional writes exactly as spec 7.5. Every status change is an UpdateItem with `ConditionExpression: #status = :expected`. Submit is one TransactWriteItems that puts `IDEMP#<clientKey>` with `attribute_not_exists(PK)` together with the request Message; a replayed key returns the existing message.
- Reads as spec 7.4: GetItem, or a Query on one partition with `begins_with` on SK. No Scan anywhere in application code. Every base-table GetItem and Query passes `ConsistentRead=True`, because the worker reads right after conditional writes.
- Adapters use boto3 low-level clients only, never the resource API. The worker shares repositories across task threads, and clients are thread-safe while resources are not.
- Only the idempotency record has a TTL (spec 7.6): attribute `ttl`, epoch seconds, 24 hours. DynamoDB's 400 KB item limit is checked before any call: an item over it raises `ItemTooLargeError` naming the item.
- Table settings match the table that exists (progress.md, 6 Nov 2026): on-demand, stream with NEW_IMAGE, point-in-time recovery on, deletion protection on. The script never deletes a resource and never changes keys.
- Every resource is tagged `project=contextforge`. Bucket: versioning off, all four public access blocks on, lifecycle rule `expire-raw-results` (prefix `raw_result/`, 30 days). Queues: `contextforge-work` is standard, with a visibility timeout of 1200 s and dead-lettering after 3 receives to `contextforge-work-dlq` (retention 14 days = 1,209,600 s).
- Unit tests run offline under moto `mock_aws` with fake credentials. Each adapter task adds one opt-in smoke test to `tests/test_aws_smoke.py`, skipped unless `CONTEXTFORGE_AWS_SMOKE=1`. Smoke data uses ids prefixed `smoke-` and is deleted afterwards.
- AWS is called only in the steps marked **live**, and those need Prerequisite P1. This phase makes no model calls.
- Shared files get additive edits only: `pyproject.toml`, `uv.lock`, `tests/conftest.py`, `tests/helpers.py`, `.env.example`, `.gitignore`, and `core/settings.py` (created here, or extended if phase 2 or 4 created it first). `worker/dependencies.py` is not changed.

## Review Focus

1. **Floats.** `Claim.value`, `ModelCall.estimated_cost_usd` and the amounts inside `structuredData` are floats. boto3 rejects Python floats and returns Decimals, so an entity holding floats must save, and must load back equal with no Decimal left inside it (Task 2 codec test, Task 4 conformance test).
2. **Read-after-write in the worker.** The plan gate and the execute stage re-read right after a conditional write, and a re-run reads the stored outcome. In real AWS an eventually consistent read can return the old status, while moto always looks consistent, so every base-table GetItem and Query must pass `ConsistentRead=True` (Task 4, pinned by a botocore parameter hook).
3. **Browser upload to a signed PUT URL from the frontend origin.** It fails without a bucket CORS rule for that origin, without the signed Content-Type header, or when the URL is not the regional SigV4 form. The stack sets CORS for `upload_cors_origins`, and `presign_put` returns the headers the client must send (Task 3 CORS assertion; Task 7 URL-shape test and live PUT).
4. **A malformed SQS body, or an ack after the visibility timeout expired.** The consumer must neither crash nor loop. `receive` logs and returns None, the message reaches the DLQ after 3 receives, and a stale ack logs and returns (Task 8).
5. **A status update on a record that does not exist, versus one whose status moved on.** The first raises `LookupError`; the second raises `StaleStatusError` carrying the actual status. Both backends behave the same, so the API can answer 404 versus 409 (Task 4 conformance test).

### Task 2: DynamoDB item shapes: keys, codec, table definition

**Files:**
- Create: `src/contextforge/core/repositories/dynamodb_items.py`, `tests/builders.py`
- Test: `tests/test_dynamodb_items.py`

**Interfaces:**
- Produces (all pure functions; no AWS calls):
  - Constants: `PK = "PK"`, `SK = "SK"`, `GSI1 = "GSI1"`, `GSI1PK = "GSI1PK"`, `GSI1SK = "GSI1SK"`, `TTL_ATTRIBUTE = "ttl"`, `KEY_ATTRIBUTES = frozenset({PK, SK, GSI1PK, GSI1SK, TTL_ATTRIBUTE})`, `MAX_ITEM_BYTES = 400 * 1024`, `IDEMPOTENCY_TTL_SECONDS = 86_400`, and `MESSAGE_PREFIX = "MSG#"`, `ARTIFACT_PREFIX = "ART#"`, `TASK_PREFIX = "TASK#"`, `CALL_PREFIX = "CALL#"`, `CHAT_PREFIX = "CHAT#"`. `Key = dict[str, str]`.
  - Partition and key helpers:
    - `user_partition(user_id) -> str`, `chat_partition(chat_id) -> str`, `request_partition(request_message_id) -> str`
    - `chat_key(user_id, chat_id) -> Key`, `message_key(chat_id, message_id) -> Key`, `artifact_key(chat_id, artifact_id) -> Key`
    - `task_key(request_message_id, task_id) -> Key`, `model_call_key(request_message_id, model_call_id) -> Key`, `idempotency_key(client_key) -> Key`
    - `artifact_index_attributes(user_id, artifact_id) -> Key`, which returns the `GSI1PK` and `GSI1SK` pair.
  - `serialize_key(key: Key) -> dict[str, Any]`: `{"PK": {"S": ...}, "SK": {"S": ...}}`, used for GetItem, ExclusiveStartKey and deletes.
  - `ttl_after(seconds: int, *, now: float | None = None) -> int`: epoch seconds.
  - `class ItemTooLargeError(ValueError)`, with attributes `key: Key` and `size_bytes: int`.
  - `encode_value(value: Any) -> dict[str, Any]`: the DynamoDB AttributeValue for one value. An `Entity` dumps through `model_dump_json(by_alias=True)`, then `json.loads(..., parse_float=Decimal)`, then `TypeSerializer`. `str` and `StrEnum` become `S`, and `None` becomes `NULL`.
  - `to_item(entity: Entity, key: Mapping[str, str], extra: Mapping[str, Any] | None = None) -> dict[str, Any]`: the full item, meaning the entity's camelCase attributes plus the key attributes plus `extra` (for example `ttl`), serialised. Raises `ItemTooLargeError` when the JSON encoding exceeds `MAX_ITEM_BYTES`. JSON overstates the DynamoDB item size, so the guard trips before DynamoDB would.
  - `from_item(item: Mapping[str, Any]) -> dict[str, Any]`: deserialises the item and drops `KEY_ATTRIBUTES`. Every Decimal becomes an `int` when integral and a `float` otherwise, recursively. The result feeds `Model.model_validate`.
  - `table_spec(table_name: str) -> dict[str, Any]`: the CreateTable kwargs. Attribute definitions `PK`, `SK`, `GSI1PK`, `GSI1SK` (all `S`); `BillingMode="PAY_PER_REQUEST"`; `GSI1` with an INCLUDE projection of `["indexStatus", "kind", "name", "chatId"]`; `StreamSpecification={"StreamEnabled": True, "StreamViewType": "NEW_IMAGE"}`; `DeletionProtectionEnabled=True`.
  - `tests/builders.py`: `make_task(task_id: str, *, request_message_id: str = "m1", goal: str = "g") -> Task` (kind `sql_analysis`, inputs `["a2"]`, PLANNED, attempt 1, timestamps `"t"`) and `make_model_call(model_call_id: str, *, usage: Usage | None = None, estimated_cost_usd: float | None = None) -> ModelCall` (request `m1`, stage `plan`, model `bedrock/amazon.nova-pro-v1:0`, context `mem:1|prompt:plan.1`, price version `2026-11-07`, outcome COMPLETED, started `"t"`).

### Task 6: Paged listings for E2, E3 and E11

The API pages chats (E2), messages (E3, newest page first) and artifacts (E11) with `limit` and `cursor` (spec 11.2). The list methods keep their phase 1 signatures; these paged variants are added for the API.

**Files:**
- Modify: `src/contextforge/core/repositories/base.py`, `shared.py`, `memory.py`, `dynamodb.py`
- Test: `tests/test_repositories.py`

**Interfaces:**
- Consumes: Task 4 `_Table`, `newest_updated_first`, `message_key`, `artifact_key`.
- Produces:
  - `base.Page[T]`: a frozen dataclass with `items: list[T]` and `next_cursor: str | None`. `base.InvalidCursor(ValueError)`, which the API maps to 400 `validation`.
  - `MessageRepository.page_by_chat(chat_id: str, *, limit: int, cursor: str | None = None) -> Page[Message]`. Pages run from the newest. Each page holds the `limit` newest messages older than the cursor, in ascending `message_id` (display order). `next_cursor` continues to older messages and is None when none remain.
  - `ArtifactRepository.page_by_chat(chat_id: str, *, limit: int, cursor: str | None = None) -> Page[Artifact]`, ascending `artifact_id`.
  - `ChatRepository.page_by_user(user_id: str, *, limit: int, cursor: str | None = None) -> Page[Chat]`, in `list_by_user` order.
  - All three raise `ValueError` when `limit < 1`, and `InvalidCursor` on a cursor they did not issue.
  - `shared.encode_cursor(position: tuple[str, ...]) -> str` (URL-safe base64 of a JSON list, unpadded) and `shared.decode_cursor(cursor: str, size: int) -> tuple[str, ...]`, which raises `InvalidCursor` on bad base64, bad JSON, or a shape that is not `size` strings. Positions: `(message_id,)`, `(artifact_id,)`, and `(updated_at, chat_id)`.
  - `shared.paginate(items: Sequence[T], *, limit: int, cursor: str | None, position: Callable[[T], tuple[str, ...]], descending: bool) -> Page[T]`. `items` are in walk order. It returns the first `limit` items strictly after the cursor's position, with `next_cursor` set only when more remain.
  - `_Table.query_page(partition: str, sk_prefix: str, *, limit: int, start: Key | None, forward: bool) -> tuple[list[dict[str, Any]], bool]`. A consistent Query with `Limit=limit + 1`, `ScanIndexForward=forward`, and `ExclusiveStartKey=serialize_key(start)` when given. Returns the first `limit` items and whether an extra item existed. The extra item is why an exactly-full last page reports no cursor.
  - Memory pages use `paginate`. DynamoDB messages and artifacts use `query_page`, with `start` rebuilt from the call's own `chat_id` and the cursor's id. DynamoDB chats use `paginate` over `list_by_user`, because spec 7.3 orders chats in memory.

1. Its latest release is under six months old and comes from `langchain-ai/langchain-aws`.
2. Its `requires_dist` admits the locked versions. As of 7 Nov 2026: version 1.2.7 (6 Nov 2026) requires `langgraph>=1.0.0`, `langgraph-checkpoint>=3.0.0,<5.0.0` and `boto3>=1.43.64`; the lock has `langgraph` 1.2.20 and `langgraph-checkpoint` 4.3.1.

4. The six `tests/test_runner.py` scenarios pass with it under moto.

`langgraph-checkpoint-dynamodb` fails condition 1 and is not used: it has a single community release (0.1.0, 13 Dec 2024, `langgraph>=0.2.53`).

- Pending writes: `SK=WR#<checkpoint_ns>#<checkpoint_id>#<task_id>#<idx>`.
- `get_tuple`: a descending consistent Query on `CP#<ns>#` (latest) or a GetItem (by id), plus a Query for that checkpoint's writes.
- `list`: a descending Query honouring `before` and `limit`.
- `put_writes`: BatchWriteItem.
- `delete_thread`: a Query, then BatchWriteItem deletes.

## Deviations from the spec, decided in this plan

- The adapters live in `core` (`core/repositories/dynamodb.py`, `core/storage.py`, `core/queue.py`), as the milestone scope directs, not in `infra/` as spec 12 lays it out. `core` now depends on boto3; moving them later touches imports only.
- Checkpoints share the `contextforge` table, through `DynamoDBSaver` from `langgraph-checkpoint-aws`. Spec 7.6 says "the tables DynamoDBSaver creates", but the package creates none, and its key schema and TTL attribute name match ours. Checkpoints get no TTL. Their growth is a phase 11 cost-review item.
- `langgraph-checkpoint-dynamodb`, named in the milestone scope, is not used: one community release (0.1.0, 13 Dec 2024).
- Paged variants are added because the API pages E2, E3 and E11 (spec 11.2 and 11.3): `MessageRepository.page_by_chat`, `ArtifactRepository.page_by_chat` and `ChatRepository.page_by_user`.
- The cursor encodes the last returned item's position (its id; for chats `updatedAt` and `chatId`), not DynamoDB's raw `LastEvaluatedKey` (spec 11.2). No key string reaches a client, a cursor cannot name another partition, and one format serves both backends. Chats are paged in memory after one Query, as 7.3 already orders them in memory.
- `pending_for_request` reads the chat partition and filters in code, where spec 7.4 names a filter on kind and status. A FilterExpression would not lower the cost, because DynamoDB charges for items read before filtering.
- `TaskRepository.save_all` makes the plan gate's Task writes one transaction, closing the phase 1 follow-up.
- The Queue Protocol gains `ack`, and `WorkMessage` gains a `receipt` that equality ignores. The in-process queue's `ack` does nothing.
- Raw-result blobs move from `chats/<chatId>/raw_results/<artifactId>.jsonl` to `raw_result/<chatId>/<artifactId>.jsonl`, so the 6 Nov lifecycle rule (prefix `raw_result/`, 30 days) applies. After 30 days a raw_result Artifact stays AVAILABLE, but its blob is gone and `get` raises `LookupError`.
- A client key replayed after its 24-hour TTL, but before DynamoDB deletes the record, still returns the original request. TTL deletion is lazy and can take up to about two days.
- Beyond the presign pair, `S3BlobStore.object_size` serves E10's HeadObject check, and the bucket gains a CORS rule for browser uploads from `upload_cors_origins`.
- The stack is adopted, not created. The table, queues and bucket made on 6 Nov 2026 are brought up to date (TTL, tags, CORS, lifecycle) and never recreated; the create path exists for a new account.
- GSI1 keeps the spec projection, without `artifactId`, matching the table that exists. Phase 5's pattern 7 query reads the id from the base item, or adds it to the projection then.
- Phase 1 has no UserRepository. Phase 7 adds one; its DynamoDB adapter (`USER#<userId>`/`PROFILE`) uses this plan's key module and codec.
- Later, not in this phase (system-design 14 row 10): Streams-to-Lambda-to-SQS dispatch (the legacy prototype files stay as reference for it), real identity, and per-user budgets at the adapter.
- Hand-offs to the other milestone 2 plans. Whichever of phases 4 and 10 merges second does this wiring:
  - The worker consumer calls `queue.ack(msg)` after `start` or `resume` returns, whether the run started or was refused.
  - API and worker startup build their dependencies with `build_backends(Settings())` and `build_checkpointer`.
  - E2, E3 and E11 call the `page_by_*` methods.
  - E9, E10 and E12 use `DirectUploads` when the blob store provides it.
  - E4 scopes the `Idempotency-Key` per user before calling `create_request`, because `IDEMP#<clientKey>` is global.
